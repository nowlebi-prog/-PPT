## 0-1. 기술 주의
- 페이지 맨 위에 `<!doctype html>`과 `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` 필수. 없으면 휴대폰에서 데스크톱 화면이 축소되어 보인다.

## 1. 절대 금지 (사용자가 이미 거절한 것들)

- **크몽 노출 금지.** 화면 어디에도 "크몽" 단어를 쓰지 않는다. 숫자 라벨은 `누적 거래 / 고객 평점 / 고객 후기`. 출처는 푸터 한 줄로만: `거래·평점·후기 수치는 외부 플랫폼 기준입니다. (2026.10)`. 크몽 의뢰 버튼·링크 금지. "공식 거래/공식 평점" 같은 표현도 금지(인증된 수치처럼 읽힘).
- **"저희", "1인", "디렉터" 금지.** 문장에 "별"을 억지로 넣지 않는다(별은 시각으로만).
- **가짜 실적 금지.** 실제 작업 이미지가 없으면 자체 샘플임을 표기한다(`※ 시안용 샘플 화면입니다.`). 집계하지 않은 숫자(TIPS 건수 등) 만들지 않는다. 네이티브 앱 출시 실적 만들지 않는다.
- **`home-v2.css`, `home-v2.js` 사용 금지** (거절된 전면 교체 시도).
- **섹션 번호(01, 02…) 화면 표기 금지.** eyebrow는 영문 단어만(`Work`, `Services`, `Pricing`).
- **글자 키우기 금지.** 아래 타입 스케일 외의 크기 쓰지 않는다. "임팩트"는 크기가 아니라 여백·대비로 만든다. 예외는 서비스 선언문 한 줄뿐(2-3장).
- **우주 배경은 첫 화면에만.** 아래 섹션은 순수 검정 바탕 + 요소 주변의 은은한 빛만.
- **인포그래픽·다이어그램을 섹션 주인공으로 쓰지 않는다.** 서비스 구간에서 카드 그리드·별자리 라벨을 넣었다가 "복잡하다"고 거절됨.
- **중구난방 배치 금지.** 레퍼런스(eyefulpresentations.com)에서 가져온 건 "스크롤에 따라 장면이 바뀌는 기획·모션"이지, 요소를 흩뿌린 레이아웃이 아니다.
- **빈 상자·깨진 이미지 금지.** 이미지가 없으면 그 칸을 만들지 않는다.
- 파란 네온, 강한 그라데이션 글자, 우주인·우주선 일러스트, 과한 글로우, 이모지 금지.

## 2. 디자인 시스템 (값 그대로 사용)

### 2-1. 색 토큰
```css
:root{
  --void:#030304;          /* 전체 바탕. 순흑에 가까운 먹색 */
  --plate:#0c0e11;         /* 한 단계 올라온 면 (거의 안 씀) */
  --line:rgba(214,220,230,.10);   /* 기본 구분선·카드 테두리 */
  --line-2:rgba(214,220,230,.22); /* 강조 테두리·버튼 테두리 */
  --silver:#c4c9d1;        /* 본문 */
  --silver-dim:#878d97;    /* 보조 글·라벨 */
  --white:#f3f4f6;         /* 제목·강조 */
  --kakao:#fee500; --kakao-ink:#191600;  /* 카카오 버튼에만 */
  --ease:cubic-bezier(.2,.7,.1,1);       /* 모든 모션의 기본 이징 */
  --gap:max(clamp(112px,13vh,140px),calc((100vh - 820px) / 2)); /* 섹션 간격 */
}
```
- 파랑(#3d7bff 등)은 **장표 이미지 안에서만** 보인다. UI 요소에 파랑을 쓰지 않는다.
- "빛"은 항상 흰색~차가운 은색 `rgba(214,224,240,α)` 계열. 따뜻한 색 금지.

### 2-2. 글꼴과 타입 스케일 (데스크톱 / 모바일 ≤860px)

- 영문 eyebrow 외에 대문자 영문 남발 금지.

### 2-3. 레이아웃
- 컨테이너 `.wrap`: `max-width:1200px; padding-inline:max(24px, env(safe-area-inset-*))` (모바일 20px).
- 12칸 그리드 `.split`: `grid-template-columns:repeat(12,minmax(0,1fr)); column-gap:24px`.
- **기본 규칙: 왼쪽 글(1~4칸 또는 1~5칸) · 오른쪽 요소(6~12칸).** 서비스만 왼쪽 7칸 / 오른쪽 5칸.
- 데스크톱에서 왼쪽 글 칸은 `position:sticky; top:104px` (작업 사례·가격). 오른쪽 요소가 길 때 글이 따라온다.
- 모든 글 요소는 **같은 왼쪽 선**에 맞춘다. 버튼·진행 막대·목록이 들쑥날쑥하면 실패.
- 섹션 높이: 데스크톱에서 한 섹션이 화면 1.5장, 모바일 2장을 넘지 않게. 넘치면 가로 밀기 카드로.

### 2-4. 섹션 간격과 구분선 (모든 섹션 공통)
```css
.sec{position:relative;isolation:isolate;padding-block:var(--gap) calc(var(--gap) * .5)}
.sec::before{ /* 가운데가 밝은 수평선 */
  content:"";position:absolute;left:50%;top:calc(var(--gap) * .25);
  width:min(1200px,calc(100% - 48px));height:1px;translate:-50% 0;
  background:linear-gradient(90deg,transparent,rgba(230,235,245,.22) 30%,rgba(230,235,245,.22) 70%,transparent)}
.sec::after{ /* 선 가운데 빛나는 점 */
  content:"";position:absolute;left:50%;top:calc(var(--gap) * .25 - 3px);
  width:7px;height:7px;margin-left:-3.5px;border-radius:50%;background:#fff;
  box-shadow:0 0 10px 2px #fff,0 0 34px 10px rgba(214,224,240,.32)}
```
- 결과: 이전 섹션 끝 → 선 → 다음 섹션 시작이 **위아래 같은 간격**(1440 기준 88px). 측정해서 확인할 것.
- 섹션마다 은은한 빛 위치를 다르게 둬서 구분한다: 작업 사례 `radial-gradient(ellipse 46% 60% at 74% 46%, rgba(150,170,205,.10), transparent 70%)`, 가격 `at 22% 40%, .08`. 새 섹션도 위치만 바꿔 같은 강도로.

### 2-6. 카드·틀 (은빛 유리 테) — 이 사이트의 핵심 질감
장표·스크린샷을 감싸는 틀은 전부 이 공식:
```css
.frame{border-radius:18px;padding:6px;
  background:linear-gradient(150deg,rgba(255,255,255,.30),rgba(255,255,255,.05) 40%,rgba(255,255,255,.12));
  box-shadow:0 40px 90px -36px rgba(0,0,0,1),0 0 80px -20px rgba(205,218,240,.14)}
.frame img{border-radius:13px}
```
- 작은 틀(썸네일)은 padding 3px, radius 10/7, 그라데이션 알파 .20/.04/.10.
- 선택된 썸네일: 그라데이션을 `#fff → rgba(255,255,255,.3) → rgba(255,255,255,.6)`로 밝히고 `translateY(-3px)`.
- 정보 카드(가격 등): `border:1px solid var(--line); border-radius:18px; background:linear-gradient(165deg,rgba(214,224,240,.05),rgba(214,224,240,.01) 55%)`. 그림자 없음. 선택 시에만 테두리 `rgba(240,243,248,.55)` + 빛 그림자.
- **모든 블록에 카드를 씌우지 말 것.** 카드는 "선택할 수 있는 것"과 "작품 틀"에만.

### 2-7. 빛 점 (브랜드 '유별 별'의 최소 단위)
```css
.spark{width:4px;height:4px;border-radius:50%;background:#fff;
  box-shadow:0 0 6px 2px #fff,0 0 16px 4px rgba(214,224,240,.4)}
```
- 활성 표시(선택된 카드 우상단, 선택된 라디오, 키워드 강조)에만 쓴다. 장식으로 뿌리지 않는다.

### 2-8. 로고 처리 (고객사 띠)
판 없이 검정 위 흰 로고. SVG·투명 PNG는 `filter:brightness(0) invert(1)`, 흰 배경 PNG는 `filter:grayscale(1) invert(1) contrast(1.4); mix-blend-mode:screen`, 색이 중요한 몇 개(삼성물산·우리은행·LH·NH)는 `grayscale(1) brightness(1.5) contrast(1.1)`. 높이 22px, 투명도 .7(hover 1). 두 줄 반대 방향 70s/80s 무한 흐름, hover 시 멈춤. 모바일은 한 줄.

### 2-9. 모션 원칙
- 이징은 전부 `var(--ease)`. 시간: 등장 .9s, 상태 변화 .3–.5s, 큰 이동 1–1.1s.
- 등장: `opacity 0→1 + translateY(14px→0)`, 요소별 0.08s씩 지연. 한 번만.
- 화면을 붙잡는(sticky) 장면은 **사이트 전체에 0개**(현재 기준). 휠을 가로로 바꾸는 스크롤 납치 금지.
- 마우스 반응은 데스크톱(`pointer:fine`)에서만, 이동량 작게(3D 기울기 4° 이하, 이동 30px 이하).
- `prefers-reduced-motion:reduce`에서 장식 모션은 끄고 내용·기능은 그대로.
- 화면 밖 애니메이션은 멈춘다(IntersectionObserver, `visibilitychange`).

### 2-10. 반응형 (모바일은 따로 설계)
- 기준점: `≤980px` 상단 메뉴 → 햄버거, `≤860px` 모바일 레이아웃.
- 모바일 메뉴: 전체 화면 시트, 2열 56px 줄, 하단에 카카오(54px) + 빠른 견적/문의 반반.
- 모바일 하단 고정 상담 바: 첫 화면 버튼을 **지나간 뒤에만** 나타남(`translateY(110%)→0`). 본문 하단에 `72px + safe-area` 여백. 입력창 포커스 시 숨김(문의 폼 구현 시).
- 가로 넘김(분류 버튼, 질문 버튼 등)은 화면 끝까지 붙여서(`margin-inline:-20px; padding-inline:20px`) 밀 수 있게 보이도록.
- 누르는 요소 최소 44px.
- 페이지 가로 스크롤 0. 390px에서 `document.documentElement.scrollWidth === 390` 확인.

## 3. 이식 방법 (실사이트 파일 구조)

- 새 CSS 파일 `assets/css/v3.css`, 새 JS `assets/js/v3.js`를 만들고 `index.html`에서 기존 CSS **뒤에** 불러온다. 시안 `template.html`의 `<style>`에서 해당 구간 CSS를 그대로 옮긴다.
- 이미지: `redesign/prototype/src/`의 파일을 `assets/img/v3/`로 복사해 상대경로로 참조(시안은 data URI로 넣었을 뿐).
  - `space-desk-sky.jpg`, `space-mob-sky.jpg` (하늘), `space-desk-planet.webp`, `space-mob-planet.webp` (행성 투명 레이어)
  - `web-peumoa.webp`, `web-clover.webp`, `web-hub.webp` (움직이는 화면 캡처, 애니메이션 WebP)
- 3D: three.js r128 `https://cdnjs.cloudflare.com/ajax/libs/three.js/r128/three.min.js` (서비스 섹션 근처에서만 지연 로드 권장). 실패하면 별 없이도 레이아웃이 깨지지 않아야 한다.
- 기존 `main.js`의 별빛 캔버스(`#stars`)·`motion.js`의 커서 글로우는 **첫 화면 새 하늘 엔진으로 대체**하되, 다른 기능이 그 파일에 의존하는지 확인 후 해당 부분만 끈다.
- 첫 화면 하늘 이미지는 `render_layers.py`로 만든 것. 다시 만들 필요 없음.

### 10 진행 방식 (`#process`) — 고정 없이 한 화면

- 오른쪽: 다섯 단계를 **가로 한 줄**(데스크톱) — 점 5개를 1px 선으로 연결, 점 아래 번호(10.5px) + 단계명(14px/600) + 한 줄 설명(12.5px, 2줄 이내). 섹션 진입 시 빛 점 하나가 왼쪽→오른쪽으로 지나가며 점을 차례로 켬(한 번). 단계 문구(확정):

  4. 제작 · 피드백 — 정한 방향으로 전체를 만들고 피드백을 반영합니다.
  5. 검수 · 납품 — 숫자·오탈자를 원본과 대조하고 PPTX 원본과 PDF로 드립니다.
